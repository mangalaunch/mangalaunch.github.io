An extension is a signed .mlsource package with one or more sources. Each source connects a website to MangaLaunch and has its own ID, settings and sign-in session.

For a working example, see MangaLaunch Official Extensions: source modules, registrations, tests and release workflows. The examples below use a fictional example.org API; adapt the endpoints and parsers to your website.

Check field names and types against the API types, manifest schema and repository index schema.

1. Prerequisites and layout

Use Node.js 22 or later. Run commands from the extension repository root.

npm ci --ignore-scripts
npm rebuild esbuild
npm test

Before writing a parser, check how the website serves its catalog, pagination, search, filters, title details, chapters, pages and recommendations. Also check login redirects and image domains. Use a structured API when one is available; otherwise extract the required fields from HTML.

For a new package, copy the template into a project directory. Replace the example URLs, IDs, license and source implementation:

my-sources/
  manifest.json
  LICENSE
  src/
    index.mjs
  assets/               # optional
  tests/
    source.test.mjs

In the official repository, source modules live in src/sources/, shared factories in src/engines/, registrations in src/definitions.mjs, and the ID-to-factory mapping in src/index.mjs. This layout is useful for a bundle; it is not required by the API. A single-source package can use the smaller structure above. Add tests for each registration and parser.

Use your own package name, extensionId, publisher key and source IDs. Mark NSFW sources with isNsfw: true and distribute them in a clearly labelled package.

Keep source, manga and chapter IDs stable: MangaLaunch uses them to link library entries, history and progress. Changing a domain does not require a new ID. To transfer an existing sourceId between packages, first update the installed owner so its signed manifest no longer lists that source. Then import the receiving package in an application version that supports source transfers and confirm the transfer of settings and sign-in sessions. Disabling a package does not release its IDs. Uninstalling it also retains ownership; reinstall the updated owner if needed. Installation never transfers ownership without approval.

When filling in the manifest:

  • capabilities and features must match the implemented methods. Set metadataOnly: true for a metadata-only source; do not advertise reading support.
  • origins covers HTML/API, imageOrigins covers covers, language flags and reader pages, and authOrigins covers domains allowed to receive authentication. Declare exact HTTPS origins without paths. Subdomains require explicit allowSubdomains.
  • Allow only the required methods and permissions: http, html, sourceSettings, sourceSession. Do not grant CDN or login domains speculatively.
  • For mirror support, declare supportsCustomBaseUrl: true, use the current ctx.baseUrl and test API, image and login behavior on the mirror. Do not globally replace independent API/CDN domains.
  • A manga web link uses web.mangaUrlTemplate with one {id}. idEncoding is pathSegment or path; composite IDs can use idPart: {separator, index}.
  • Source branding uses branding: {icon: "assets/site.png", accentColor: "#123456"}. PNG/JPEG/WebP icons must be local signed files of at most 256 KiB. Branding belongs to the extension.
  • presentation.coverFit accepts contain or cover. network.transportProfile: "host.platform.v1" selects the platform HTTP/media transport. Declare the minimum application version supporting the features you use.

3. Implementing a source

The entry point is a synchronous export default function createSource(ctx) that returns the source methods. Keep imports and factory creation free of HTTP, HTML, settings and authentication calls: the application also checks packages offline.

The runtime provides JavaScript, Promise, URL/URLSearchParams and UTF-8 TextEncoder/TextDecoder. It has no Node.js, process, require, filesystem, sockets or browser DOM. Import dependencies by relative paths to signed package files; remote imports are unavailable.

Here is a source for the example JSON API. Save it as src/index.mjs:

const invalid = () => Object.assign(
  Error('Unexpected API response.'), {code: 'parse_error', phase: 'parse'},
);
const array = value => {
  if (!Array.isArray(value)) throw invalid();
  return value;
};
const text = value => {
  if (typeof value !== 'string' || !value.trim()) throw invalid();
  return value;
};
const record = value => {
  if (!value || typeof value !== 'object' || Array.isArray(value)) throw invalid();
  return value;
};
const manga = input => {
  const row = record(input);
  return {
    id: text(row.id), title: text(row.title),
    coverUrl: row.cover ?? null, description: row.description ?? null,
    secondaryTitle: null, author: row.author ?? null, artist: null,
    status: null, type: null, ageRating: null, rating: null,
    releaseYear: null, pageCount: null, languageFlagUrl: null,
    tags: array(row.tags ?? []).map(text),
  };
};

export default function createSource(ctx) {
  async function get(path, query = {}) {
    const url = new URL(path, ctx.baseUrl);
    for (const [key, value] of Object.entries(query)) {
      if (value !== '') url.searchParams.set(key, String(value));
    }
    return record((await ctx.http.request({
      method: 'GET', url: url.href, responseType: 'json',
    })).body);
  }
  async function list(sort, page, searchTerm = '', selectedFilters = {}) {
    const tags = selectedFilters.genres ?? [];
    const values = prefix => tags
      .filter(value => value.startsWith(prefix))
      .map(value => value.slice(prefix.length)).join(',');
    const response = await get('/api/titles', {
      sort, page, q: searchTerm,
      genres: values('include:'), excludeGenres: values('exclude:'),
    });
    return array(response.items).map(manga);
  }
  return {
    async getPopular({page = 1} = {}) { return list('popular', page); },
    async getLatest({page = 1} = {}) { return list('latest', page); },
    async search({searchTerm = '', page = 1, selectedFilters = {}} = {}) {
      return list(selectedFilters.sort?.[0] ?? 'relevance',
        page, searchTerm, selectedFilters);
    },
    async getFilters() {
      return [{
        key: 'sort', label: 'Order', caption: null, kind: 'sort',
        supportsDirection: false, defaultValues: [],
        options: ['relevance', 'popular', 'latest'].map(value => ({
          value, label: value, caption: null,
        })),
      }, {
        key: 'genres', label: 'Genres', caption: null,
        kind: 'triStateMultiSelect', defaultValues: [],
        options: [{value: 'action', label: 'Action', caption: null}],
      }];
    },
    async getDetails({mangaId}) {
      return manga(await get('/api/titles/' + encodeURIComponent(mangaId)));
    },
    async getChapters({mangaId}) {
      const response = await get('/api/titles/' +
        encodeURIComponent(mangaId) + '/chapters');
      return array(response.items).map(input => {
        const row = record(input);
        if (!Number.isFinite(row.number)) throw invalid();
        return {
          id: text(row.id), title: text(row.title), number: row.number,
          uploadedAt: row.uploadedAt ?? null,
          access: {type: 'available', availableAt: null,
            priceLabel: null, message: null},
        };
      });
    },
    async getPages({chapterId}) {
      const response = await get('/api/chapters/' +
        encodeURIComponent(chapterId) + '/pages');
      return array(response.images).map((imageUrl, index) => ({
        index, imageUrl: text(imageUrl),
      }));
    },
    async getRecommendations({mangaId, page = 1}) {
      const response = await get('/api/titles/' +
        encodeURIComponent(mangaId) + '/recommendations', {page});
      if (typeof response.hasNextPage !== 'boolean') throw invalid();
      return {items: array(response.items).map(manga),
        page, hasNextPage: response.hasNextPage};
    },
  };
}

The example website returns {items: [...]} for catalogs and chapters, a manga object for details, {images: [...]} for pages, and {items: [...], hasNextPage: boolean} for recommendations. Adapt the parser to the actual responses from your website.

Return JSON data: use null for nullable fields and arrays for lists. Do not return undefined, NaN, functions or DOM objects. Image URLs must be absolute. Catalog pages start at 1; PageDto.index starts at 0 and has no gaps or duplicates. Chapter IDs must be unique, and chapter numbers must be finite; keep fractional numbers. Dates use ISO-8601 with a timezone, preferably UTC, or null.

Use ChapterDto.access to distinguish available, temporarilyUnavailable and paid. Include availableAt, priceLabel and message when the website provides them. Report paid access as an access restriction rather than a network failure. A metadata-only source still implements the required chapter and page methods, returning empty arrays.

4. HTTP, HTML and images

Send requests through ctx.http.request. The application attaches the source session and applies transport permissions. HTTPS, origin, port and permission checks run again on each redirect.

Declare authentication in the manifest instead of setting Cookie, Authorization, Host or User-Agent yourself. Select a userAgentProfile: app, browser, reader or mobileSafari. Referer and Origin must use allowed origins. The HTTP reference below lists the supported public API headers.

Extract related HTML fields in one nested projection:

const response = await ctx.http.request({
  method: 'GET', url: new URL('/catalog', ctx.baseUrl).href,
  responseType: 'text',
});
const cards = await ctx.html.extract(response.body, {
  baseUrl: response.url, selector: '.title-card', all: true,
  fields: {
    title: {selector: 'h3', text: true},
    href: {selector: 'a', attr: 'href', absoluteUrl: true},
    cover: {selector: 'img', attr: 'data-src', absoluteUrl: true},
  },
});

Run this example inside an asynchronous source method and declare the html permission. A projection returns data, not DOM nodes. Its fields include fields, all, required, text, attr, absoluteUrl, html, outerHtml, ascend, nextSibling, directChildren and tagName.

exclude removes matching descendants from a text projection. normalizeWhitespace: false keeps internal whitespace. containsText: ["term"] checks for 1–8 literal substrings, each up to 256 characters, and returns a boolean. It does not run a regular expression and cannot share a node with another output mode.

getPages returns image URLs. The application’s media broker downloads and caches covers and pages, using the declared headers and session. Keep signed CDN query parameters intact. For supported image transformations, use media.transform; the manifest cannot run an arbitrary decoder.

5. Filters, settings and authentication

Filters: complete contract

Declaration, request and response are different data

  1. Declare the filters capability and implement getFilters({refresh?}).
  2. Return a FilterDto array from getFilters, not {filters: [...]}, selected values or HTTP parameters. Array order determines filter order; options order determines option order.
  3. The application builds controls from that array and sends the selection to search({searchTerm, page, selectedFilters}).
  4. The source translates that selection into the website's API/HTML request and returns MangaDto[]. Keys are not automatically mapped to website query/body parameters.
interface FilterOptionDto {
  value: string;
  label: string;
  caption: string | null;
}
interface FilterDto {
  key: string;
  label: string;
  caption: string | null;
  kind: 'toggle' | 'text' | 'singleSelect' | 'multiSelect'
      | 'triStateMultiSelect' | 'sort';
  options: FilterOptionDto[];
  defaultValues: string[];
  supportsDirection?: boolean;
}
interface SourceQueryDto {
  searchTerm: string;
  page: number;
  selectedFilters: Record<string, string[]>;
}
FilterDto field Contract
key A nonempty stable string, unique throughout the filter list. Selections use this key. genres, format and sort are conventions, not required names.
label A nonempty user-facing label. Do not use it as an API ID.
caption An explanation or null; plain text, not HTML controls.
kind Exactly one of the six types below; arbitrary types are unsupported.
options An array of {value, label, caption}. Use [] for toggle/text; enumerate options for other kinds.
defaultValues An array of API values. A nonempty array is allowed only for multiSelect, and every value must exist in options. Use [] for other kinds.
supportsDirection An optional boolean, default true. Relevant to sort; false hides direction selection.

In FilterOptionDto, value is the string ID sent to the source, label is its nonempty display name, and caption is an explanation or null. Keep numeric website IDs as strings, for example "42"; convert them only when the website API needs a number. Values must be unique within a filter. Avoid giving different values the same label: users cannot distinguish the resulting chips.

An option may have value: "" for a neutral choice such as “Any”. In singleSelect and sort, this clears the selection. An empty string cannot be a meaningful ID or appear in defaultValues. The UI ignores options for toggle and text.

Return the declared fields explicitly: use caption: null, options: [] and defaultValues: [] when empty. Some omitted arrays are accepted for compatibility, but new sources should return the complete DTO.

Decoding limits: 256 filters, 10000 options and 10000 defaultValues per filter. Key/label/value/caption strings are limited to 16384 characters without NUL; required strings cannot be whitespace-only. Choose short machine keys, especially for filterBindings, whose key references are limited to 128 characters. Duplicate keys, duplicate values, unknown kinds, invalid supportsDirection and unsupported defaults reject the entire list.

How each kind transmits its selection

Each selectedFilters entry is a string[]. Booleans, numbers, null, nested objects and scalar strings are invalid here. Keys and option values are case-sensitive; do not translate or URL-encode them before passing them to the source.

kind Example selectedFilters entry Neutral state and handling
toggle "availableOnly": ["true"] Disabling removes the key. Check values.includes("true"); the UI does not send "false".
text "author": ["Name One, Name Two"] One string in the first element. Empty input removes the key. Do not expect an array of separate terms.
singleSelect "format": ["manga"] One API value. No selection means an absent key; also treat [] as no selection.
multiSelect "languages": ["en", "ru"] Bare values without prefixes. An absent key means defaults; explicit [] clears everything.
triStateMultiSelect "genres": ["include:action", "exclude:horror"] Each value is ignored/included/excluded. Ignore is omitted; an empty selection removes the key.
sort "sort": ["latest", "desc"] or ["title", "asc"] First element is the field, second is direction. Without the second, the UI assumes desc. With supportsDirection=false, only ["latest"] is sent.

The text editor can show terms as chips and join active terms with ,, but the source still receives one string. There is no shared CSV, author-ID or search-syntax parser. Define the meaning in your source and explain it in caption. Keep aliases such as name | alias intact.

For triState, declare the unprefixed value, for example value: "action". The selection arrives as "include:action" or "exclude:action". Only these prefixes are supported; -action, !action, booleans and ignore:action are invalid. Remove the first prefix and keep the rest of the ID, including any further colons.

The UI cannot both include and exclude the same option. Old saved selections can still contain conflicts or removed options, so deduplicate values, validate them against current options and decide how to resolve conflicts. In the example below, inclusion wins; your website may require another policy.

Defaults, clearing and reset

Suppose languages.defaultValues = ["en", "ru"]:

State Website selection
selectedFilters = {} en and ru: the defaults
{"languages": ["ja"]} Only ja
{"languages": []} Explicitly no languages; defaults are not restored
{"languages": ["en", "ru"]} Equivalent to defaults; the UI may omit this redundant key
Global filter reset button Selection becomes {}, so defaults apply again

MangaLaunch uses defaults to display multiSelect, but does not insert them into selectedFilters. Apply defaults in the source when the key is missing. Use selectedFilters.languages ?? defaults; a length check would incorrectly replace an explicit [] after the user clears the filter.

Other kinds have no declarative initial selection. defaultValue, selected, checked and min/max are not FilterDto fields. Set the initial order in getPopular, getLatest and search, rather than in a sort filter’s defaultValues.

Explicit empty arrays reach the source unchanged. Entries whose nonempty arrays contain only whitespace strings are removed before the request; do not use them as control signals.

Catalog routing and sort order

  • Empty searchTerm and selectedFilters: discovery calls getPopular; latest calls getLatest.
  • Search text or any selectedFilters entry, including explicit []: calls search. Therefore search must handle searchTerm: "", not just title searches.
  • In a filtered feed without search text, the application may add ordering from the first kind=sort declaration: latest/new for latest, or popular/discover for discovery, matched against value or label. An existing user selection is retained.
  • Without a matching option, the source supplies its own default order. SourceQueryDto has no feedKind or separate “called from latest” flag; do not infer it from call order.
  • getLatest must use the same server order as the corresponding explicit filter selection. supportsDirection: false means fixed API order; ignore any direction retained in an old preset.
  • Search/filter changes restart pagination at 1. Do not share one cursor between different selections or simultaneous operations; isolate API cursors by the normalized query.

Complete module handling all six kinds

Save the next example as src/catalog-filters.mjs. Replace language[], genre[] and the other fictional website parameters with real ones. Use append for repeated query parameters; String(array) produces a different request.

const choices = {
  format: [['manga', 'Manga'], ['manhwa', 'Manhwa']],
  languages: [['en', 'English'], ['ru', 'Russian'], ['ja', 'Japanese']],
  genres: [['action', 'Action'], ['drama', 'Drama'], ['horror', 'Horror']],
  sort: [['relevance', 'Relevance'], ['popular', 'Popular'],
    ['latest', 'Latest updates'], ['title', 'Title']],
};
const allowed = Object.fromEntries(Object.entries(choices)
  .map(([key, rows]) => [key, new Set(rows.map(([value]) => value))]));
const languageDefaults = ['en', 'ru'];
const options = key => choices[key].map(([value, label]) => ({
  value, label, caption: null,
}));

export function catalogFilters() {
  return [
    {key: 'availableOnly', label: 'Available only', caption: null,
      kind: 'toggle', options: [], defaultValues: []},
    {key: 'author', label: 'Author', caption: 'Name or alias',
      kind: 'text', options: [], defaultValues: []},
    {key: 'format', label: 'Format', caption: null,
      kind: 'singleSelect', options: options('format'), defaultValues: []},
    {key: 'languages', label: 'Languages', caption: null,
      kind: 'multiSelect', options: options('languages'),
      defaultValues: [...languageDefaults]},
    {key: 'genres', label: 'Genres', caption: null,
      kind: 'triStateMultiSelect', options: options('genres'), defaultValues: []},
    {key: 'sort', label: 'Order', caption: null,
      kind: 'sort', options: options('sort'), defaultValues: [],
      supportsDirection: true},
  ];
}

export function buildSearchRequest(ctx, query = {}) {
  const selected = query.selectedFilters ?? {};
  const values = key => Array.isArray(selected[key])
    ? selected[key].filter(value => typeof value === 'string') : [];
  const known = key => [...new Set(values(key))]
    .filter(value => allowed[key].has(value));
  const searchTerm = typeof query.searchTerm === 'string' ? query.searchTerm : '';
  const page = Number.isSafeInteger(query.page) && query.page >= 1 ? query.page : 1;
  const url = new URL('/api/titles', ctx.baseUrl);
  url.searchParams.set('page', String(page));
  if (searchTerm.trim()) url.searchParams.set('q', searchTerm);

  if (values('availableOnly').includes('true')) {
    url.searchParams.set('available', 'true');
  }
  const author = values('author')[0];
  if (author?.trim()) url.searchParams.set('author', author);
  const format = known('format')[0];
  if (format) url.searchParams.set('format', format);

  // An absent key applies defaults; an explicit [] removes every language.
  const languages = Array.isArray(selected.languages)
    ? known('languages') : languageDefaults;
  for (const value of languages) url.searchParams.append('language[]', value);

  const included = new Set();
  const excluded = new Set();
  for (const raw of values('genres')) {
    if (raw.startsWith('include:') && allowed.genres.has(raw.slice(8))) {
      included.add(raw.slice(8));
    } else if (raw.startsWith('exclude:') && allowed.genres.has(raw.slice(8))) {
      excluded.add(raw.slice(8));
    }
  }
  // Normal UI input is exclusive. For a conflicting stale selection,
  // this example gives inclusion priority.
  for (const value of included) {
    excluded.delete(value);
    url.searchParams.append('genre[]', value);
  }
  for (const value of excluded) url.searchParams.append('excludeGenre[]', value);

  const rawSort = values('sort');
  const sort = allowed.sort.has(rawSort[0])
    ? rawSort[0] : searchTerm.trim() ? 'relevance' : 'popular';
  url.searchParams.set('sort', sort);
  url.searchParams.set('direction', rawSort[1] === 'asc' ? 'asc' : 'desc');
  return {method: 'GET', url: url.href, responseType: 'json'};
}

export function createCatalogMethods(ctx, mapManga) {
  async function search(query) {
    const response = await ctx.http.request(buildSearchRequest(ctx, query));
    if (!response.body || !Array.isArray(response.body.items)) {
      throw Object.assign(Error('Invalid catalog response.'),
        {code: 'parse_error', phase: 'parse'});
    }
    return response.body.items.map(mapManga);
  }
  return {
    async getFilters() { return catalogFilters(); },
    search,
    getPopular({page = 1} = {}) {
      return search({page, searchTerm: '',
        selectedFilters: {sort: ['popular', 'desc']}});
    },
    getLatest({page = 1} = {}) {
      return search({page, searchTerm: '',
        selectedFilters: {sort: ['latest', 'desc']}});
    },
  };
}

To use this module with section 3, import createCatalogMethods from ./catalog-filters.mjs and call const catalog = createCatalogMethods(ctx, manga) inside createSource. Spread ...catalog into the returned object, replacing the earlier getPopular, getLatest, search and getFilters methods. Keep the details, chapters, pages and recommendations methods from section 3.

The module handles:

  • Returns declarations for every supported kind and applies defaults to ordinary catalogs as well.
  • Reads only known keys and API values, ignoring unknown old values. It does not forward URLs, arbitrary sort fields or query fragments from selectedFilters.
  • Preserves text, encodes special characters once, and handles include/exclude, repeated parameters and asc/desc.
  • Stores no active-query state; multiple search operations can run concurrently.

Translate selectedFilters into the website’s request format: GET query parameters, JSON POST or form POST. The source is responsible for IDs, numbers, inclusion/exclusion arrays and body fields. For a form, pass a URLSearchParams string with the correct Content-Type; an object body is not encoded as a form automatically.

There are no filter kinds for ranges, groups, dependent dropdowns, remote autocomplete, custom HTML or custom controls. Represent a range with two text filters and validate its bounds when building the request. Dropdowns need a complete flat options list; getFilters receives no option-search text.

Dynamic options and refresh

If the website’s options can change, declare supportsFilterRefresh: true. A user refresh calls getFilters({refresh: true}); ordinary calls pass false or omit the argument. MangaLaunch caches successful snapshots and shares concurrent ordinary reads. Failed loads can be retried. A search or latest request may run before getFilters.

Keep source-side caches inside the factory. This src/filter-cache.mjs helper supports forced refresh:

export function cachedFilterLoader(loadFilters) {
  let snapshot;
  let pending;
  let generation = 0;
  return async function getFilters({refresh = false} = {}) {
    if (refresh) {
      generation++;
      snapshot = undefined;
      pending = undefined;
    }
    if (snapshot !== undefined) return snapshot;
    if (pending) return pending;
    const current = generation;
    const task = Promise.resolve().then(loadFilters).then(filters => {
      if (!Array.isArray(filters)) {
        throw Object.assign(Error('Invalid filter response.'),
          {code: 'parse_error', phase: 'parse'});
      }
      if (generation === current) snapshot = filters;
      return filters;
    });
    pending = task;
    try { return await task; }
    finally { if (pending === task) pending = undefined; }
  };
}

Inside createSource, use const getFilters = cachedFilterLoader(() => loadFiltersFromSite(ctx)). Your loader must validate the response and return a complete FilterDto[] with stable values. The helper retries failures and prevents an older response from overwriting a newer snapshot. Static filters need neither caching nor refresh.

Saved filters and positions store key and value. You can rename a label without breaking them; changing a key or value breaks the link. Decide how to handle options removed by the website and document that choice. If loading options fails, report the error rather than returning an empty list.

Manga chips and filterBindings

Use filterBindings to connect title-card chips to filters. It accepts the roles author, artist and tags; each value is a filter key, not an option ID. For example: {"author": "author", "tags": "genres"}.

  • Author/artist bind to kind=text and send the full display name as one string. Resolve names to API IDs inside search if required.
  • The shared MangaDto.tags list can contain genres, tags, themes and formats. The application matches chip labels to option.label on suitable singleSelect/multiSelect/triStateMultiSelect filters.
  • Exact labels outrank partial matches; bindings break ties. A genre match can choose genres even when tags is the preferred binding.
  • A triState chip becomes include:value; single/multi chips use the bare value. A suitable text filter can be used without an option match; absent any match, the application opens text search.
  • Return clean matching names without badge counts, unrelated descendant text or HTML. Preserve complete author aliases.

Required filter tests

Test each kind with a missing key, an explicit [], defaults and a cleared selection. Check reset, every sort field and direction, fixed-direction sorting, include/exclude/ignore, conflicts and removed options. Include text with commas and special characters, filtering with an empty searchTerm, changes after page 1, concurrent selections, refresh after failure and old/new response races. Check genre, tag and author/artist chips separately.

Authentication

Login, CAPTCHA and SSO run in the application’s WebView. The source declares how to recognise and export the session. Add the account capability, features.auth: true, the sourceSession permission and an auth block:

{

  "cookieOrigins": ["https://example.org"],

Match network.authOrigins and cookieOrigins to the actual login and API domains. A parent cookie domain needs its own explicit grant. Do not export a session to a CDN just to load images. Set completionUrl and successUrl from the website’s login flow, and keep features.authCompletion consistent with them.

For Bearer sessions, use host.session.v1 and the declarative rules bearer, cookieAll/cookieAny, tokenStorageKeys, tokenPath, tokenFields, tokenTypePath, tokenType and tokenCookieNames. });

This request needs an allowed POST method and URL, plus an exported accessToken. Pass authRevision so that a session change cancels outdated work. Never cache or log tokens, cookies, passwords or session snapshots.

6. Performance, limits and errors

  • Every sourceId has separate settings, cookies, tokens and browser profile, even when a website or engine is shared.
  • Several methods on one factory can run concurrently: the default is 3 operations, configurable by the user from 1 to 5. Do not keep the current mangaId, page, temporary response or mutable cursor in a shared factory field. Use local argument variables.
  • Use Promise.all for independent requests within the limits. Do not parallelize dependent login steps or pagination sharing a server cursor.
  • For paired Details/Chapters/Recommendations reads from one page, reuse one load and projection with recent: include the helper in your project and create the cache inside the factory. Defaults are 2 entries and 15 seconds after completion; identical in-flight requests are shared and failures are removed. Do not use this cache for manually refreshed catalogs, POST or writes.
  • Runtime packages contain only used source files, data, icons and the license. Tests, node_modules, SDK bootstrap and private keys are excluded.
Limit Value
Sources per package 1–64
network.maxConcurrentRequests 1–8; current bundles declare 6
Application HTTP scheduler up to 32 simultaneous requests, up to 8 per origin; queue 1024
Image loading budget 16 overall / 8 per source; other limits also apply
HTTP timeout 250–30000 ms
Operation wait / method execution up to 30 s in the context queue / up to 30 s after starting
Context operation queue up to 64 waiting operations, in addition to 1–5 active ones
HTTP request body up to 256 KiB
HTTP text/JSON response up to 4 MiB
HTTP bytes response up to 1 MiB

The effective HTTP limit may be lower than the manifest allows. It is separate from the number of source methods that can run at once.

If the website changes its response format, return parse_error or invalid_response. Return an empty list only when there are no results or pagination has ended. Other standard codes include auth_required, challenge_required, rate_limited, not_found, chapter_unavailable, timeout and cancelled; the reference below lists them all. To report a parsing failure: Object.assign(Error("Unexpected catalog response."), {code: "parse_error", phase: "parse"}).

Preserve the host’s original error code. Do not cycle through domains to hide 403, challenges or 429, and do not automatically repeat POST requests or login. Log short diagnostic events through ctx.log.info(event, fields) without secrets.

9. Publishing on GitHub

Manual release of your own package

For both manual releases and CI:

  1. Release a tested commit with a new SemVer version; do not overwrite a published version or its bytes.
  2. Preserve extensionId, source IDs and publisher key during ordinary updates. Handle key rotation or revocation explicitly; a new key supplied by a downloaded package cannot approve itself.
  3. Add a signed index binding the repository, version, tag, archive, hash and source IDs:

The index expires after 30 days; refresh it before expiry. extensions-index.ed25519 is a separate binary signature, not JSON or base64. Sign both the index and the package.

For a manual release, create a tag on the tested commit and attach these five files to a GitHub Release:

For a prerelease, add a SemVer suffix and mark the GitHub Release as a prerelease. Describe source changes, the minimum application version, new permissions and any testing gaps in the release notes. Publish the package, public key record, checksum and signed index. Keep the private key private.

Release automation

The official extension repository has a release workflow you can read as an example. For your project, protect the main branch and create a protected release environment with your own keys and settings:

  • Add reviewers and release tag restrictions if needed.

This reference describes the data exchanged with MangaLaunch. Website responses can have a different shape; the source converts them to these contracts. HTTP request field Rules
method, url, responseType Required; method must be in network.methods. URL is HTTPS without credentials or a fragment, on an allowed origin with the same port. The network broker limits URLs to 8192 characters.

String bodies default to text/plain; charset=utf-8; JSON bodies default to application/json, unless explicitly overridden. Form POST example inside an asynchronous method:

const body = new URLSearchParams({q: 'A & B', page: '1'}).toString();
const response = await ctx.http.request({
  method: 'POST',
  url: new URL('/api/search', ctx.baseUrl).href,
  responseType: 'json',
  headers: {'Content-Type': 'application/x-www-form-urlencoded; charset=utf-8'},
  body,
});

HEAD can also probe an allowed image origin and does not return image content. GET does not accept a body. GET/HEAD follow up to 5 redirects with fresh URL/session checks; POST redirects are not replayed automatically.

Successful responses contain the final url, status, body and safe lowercase headers: content-type, content-length, cache-control, etag, last-modified, retry-after, location, x-total-count, cf-mitigated. Set-Cookie is not exposed to the script; the application applies cookies separately within the allowed session.

responseType: "text" returns a string, "json" a parsed JSON value, and "bytes" an array of numbers from 0 to 255. The host respects the declared HTTP encoding, including Windows-1251. Preserve errors for unsupported encodings or malformed JSON.

Non-2xx responses throw SourceHostError: 401 → auth_required, 403 → access_denied, 404 → not_found, 429 → rate_limited, others → invalid_response; cf-mitigated: challenge produces challenge_required. Parse a safe error.body from your own endpoint when needed to identify access restrictions. Do not expect a normal response.status=404 instead of an exception.

10.6. Errors and diagnostics

SourceHostError is an Error with code and phase. It may also contain httpStatus, retryAfterSeconds, access and body. Use a short stage name for phase, not a stack trace, HTML or token. Preserve codes from host errors; add code and phase when throwing your own.

The complete API v1 code union:

cancelled, timeout, offline, network, rate_limited, auth_required,
challenge_required, not_found, title_not_found, chapter_not_found,
chapter_unavailable, parse_error, invalid_response, permission_denied,
unsupported, incompatible_api, resource_limit, runtime_crashed,
auth_session_changed, source_unavailable, access_denied

not_found reports a missing resource; title_not_found and chapter_not_found identify it more precisely. chapter_unavailable with access describes a reading restriction. permission_denied indicates a permission or call-contract violation; unsupported an unavailable feature; resource_limit an exhausted budget. Report cancellation and session changes as errors rather than empty results.

ctx.log.info accepts an event name and an object whose values are strings, numbers or booleans. Keep responses, Error objects, cookies and personal data out of logs.

10.7. Signed repository index contract

An index contains schemaVersion=1, repositoryId (lowercase owner/repo), serial, generatedAt, expiresAt, publisherKeyId, channel and packages. channel is stable/prerelease; timestamps use UTC seconds and Z.

Each packages entry contains extensionId, version, releaseTag, assetName, size, sha256, sourceApiVersion, minRuntimeAbi, minAppVersion, sourceIds and channel. These are checked against an independently verified archive. Do not replace assetName with an external download URL. The schema permits up to 128 packages, but the provided sign_repository_index.mjs creates an index for one supplied archive.

The canonical manifest is signed with Ed25519 using the prefix MangaLaunch source package v1\n; the index uses MangaLaunch source repository v1\n. The signatures are not interchangeable. Use the packer and index signer to produce the canonical bytes. When an index expires, metadata updates stop, but installed packages can still run offline. An older archive or removing a repository does not bypass key revocation or pinning.

Быстрый переход: пример источника · фильтры · публикация · справочник API.

Расширение — подписанный пакет .mlsource с одним или несколькими источниками. Каждый источник подключает к MangaLaunch отдельный сайт и имеет свой ID, настройки и сессию входа.

Пример работающего проекта — MangaLaunch Official Extensions: модули источников, регистрации, тесты и процессы выпуска. В примерах ниже используется вымышленный API example.org; адаптируйте адреса и парсеры под свой сайт.

Названия и типы полей сверяйте с типами API, схемой manifest и схемой индекса репозитория.

1. Подготовка и структура

Нужен Node.js 22 или новее. Команды выполняются из корня репозитория расширений.

npm ci --ignore-scripts
npm rebuild esbuild
npm test

До написания парсера проверьте, как сайт отдаёт каталог, следующие страницы, поиск, фильтры, карточку тайтла, главы, изображения и рекомендации. Отдельно разберите вход, перенаправления и домены изображений. Если есть структурированный API, используйте его; в остальных случаях извлекайте нужные поля из HTML.

Для нового пакета скопируйте шаблон в каталог проекта. Замените адреса, ID, лицензию и реализацию источника:

my-sources/
  manifest.json
  LICENSE
  src/
    index.mjs
  assets/               # при необходимости
  tests/
    source.test.mjs

В официальном репозитории модули источников находятся в src/sources/, общие фабрики — в src/engines/, регистрации — в src/definitions.mjs, а соответствия ID и фабрик — в src/index.mjs. Такая структура удобна для набора источников, но API её не требует. Для одного источника достаточно структуры выше. Для каждой регистрации и парсера добавьте тесты.

Задайте собственные название пакета, extensionId, ключ издателя и ID источников. Для NSFW-источников укажите isNsfw: true и выпускайте их в явно обозначенном пакете.

Сохраняйте ID источников, тайтлов и глав: по ним MangaLaunch связывает библиотеку, историю и прогресс. При смене домена ID менять не нужно. Чтобы передать существующий sourceId другому пакету, сначала обновите установленный пакет-владелец: его подписанный manifest больше не должен содержать этот источник. Затем импортируйте принимающий пакет в версии приложения с поддержкой передачи источников и подтвердите перенос настроек и сессий входа. Отключение и удаление пакета не освобождают его ID; при необходимости переустановите обновлённый пакет-владелец. Без подтверждения владение не передаётся.

При заполнении manifest:

  • capabilities и features должны соответствовать реально реализованным методам. Для источника только с метаданными укажите metadataOnly: true; не объявляйте доступное чтение.
  • origins — HTML/API, imageOrigins — обложки, флаги языков и страницы, authOrigins — домены, которым разрешена авторизация. Указывайте точные HTTPS origins без путей. Для поддоменов требуется явное allowSubdomains.
  • Разрешайте только нужные методы и permissions: http, html, sourceSettings, sourceSession. Не добавляйте CDN и домены входа «на всякий случай».
  • Для смены зеркала объявите supportsCustomBaseUrl: true, используйте актуальный ctx.baseUrl и проверьте поведение API, изображений и входа на зеркале. Не заменяйте глобально домены независимых API/CDN.
  • Ссылка на тайтл задаётся через web.mangaUrlTemplate с одним {id}. idEncoding — pathSegment или path; для составного ID доступен idPart: {separator, index}.
  • Иконка источника задаётся через branding: {icon: "assets/site.png", accentColor: "#123456"}. PNG/JPEG/WebP — до 256 КиБ, локальный подписанный файл. Оформление принадлежит расширению.
  • presentation.coverFit принимает contain или cover. network.transportProfile: "host.platform.v1" выбирает платформенный HTTP/media-транспорт. Указывайте минимальную версию приложения, поддерживающую используемые возможности.

3. Реализация источника

Точка входа — синхронная export default function createSource(ctx), которая возвращает методы источника. Во время импорта и создания фабрики не выполняйте запросы HTTP, разбор HTML, чтение настроек или авторизацию: приложение проверяет пакет в том числе без сети.

В среде выполнения доступны JavaScript, Promise, URL/URLSearchParams и UTF-8 TextEncoder/TextDecoder. Node.js, process, require, файловой системы, сокетов и браузерного DOM нет. Зависимости импортируются по относительным путям к подписанным файлам пакета; удалённые импорты недоступны.

Метод Аргументы Результат
getPopular {page} MangaDto[], capability browse
getLatest {page} MangaDto[], capability latest
search {searchTerm, page, selectedFilters} MangaDto[], capability search
getFilters {refresh?} FilterDto[], capability filters
getDetails {mangaId} MangaDto, обязательный метод
getChapters {mangaId} ChapterDto[], обязательный метод
getPages {mangaId, chapterId} PageDto[], обязательный метод
getRecommendations {mangaId, page} {items, page, hasNextPage}, capability recommendations

Источник для примера JSON API. Сохраните его как src/index.mjs:

const invalid = () => Object.assign(
  Error('Unexpected API response.'), {code: 'parse_error', phase: 'parse'},
);
const array = value => {
  if (!Array.isArray(value)) throw invalid();
  return value;
};
const text = value => {
  if (typeof value !== 'string' || !value.trim()) throw invalid();
  return value;
};
const record = value => {
  if (!value || typeof value !== 'object' || Array.isArray(value)) throw invalid();
  return value;
};
const manga = input => {
  const row = record(input);
  return {
    id: text(row.id), title: text(row.title),
    coverUrl: row.cover ?? null, description: row.description ?? null,
    secondaryTitle: null, author: row.author ?? null, artist: null,
    status: null, type: null, ageRating: null, rating: null,
    releaseYear: null, pageCount: null, languageFlagUrl: null,
    tags: array(row.tags ?? []).map(text),
  };
};

export default function createSource(ctx) {
  async function get(path, query = {}) {
    const url = new URL(path, ctx.baseUrl);
    for (const [key, value] of Object.entries(query)) {
      if (value !== '') url.searchParams.set(key, String(value));
    }
    return record((await ctx.http.request({
      method: 'GET', url: url.href, responseType: 'json',
    })).body);
  }
  async function list(sort, page, searchTerm = '', selectedFilters = {}) {
    const tags = selectedFilters.genres ?? [];
    const values = prefix => tags
      .filter(value => value.startsWith(prefix))
      .map(value => value.slice(prefix.length)).join(',');
    const response = await get('/api/titles', {
      sort, page, q: searchTerm,
      genres: values('include:'), excludeGenres: values('exclude:'),
    });
    return array(response.items).map(manga);
  }
  return {
    async getPopular({page = 1} = {}) { return list('popular', page); },
    async getLatest({page = 1} = {}) { return list('latest', page); },
    async search({searchTerm = '', page = 1, selectedFilters = {}} = {}) {
      return list(selectedFilters.sort?.[0] ?? 'relevance',
        page, searchTerm, selectedFilters);
    },
    async getFilters() {
      return [{
        key: 'sort', label: 'Order', caption: null, kind: 'sort',
        supportsDirection: false, defaultValues: [],
        options: ['relevance', 'popular', 'latest'].map(value => ({
          value, label: value, caption: null,
        })),
      }, {
        key: 'genres', label: 'Genres', caption: null,
        kind: 'triStateMultiSelect', defaultValues: [],
        options: [{value: 'action', label: 'Action', caption: null}],
      }];
    },
    async getDetails({mangaId}) {
      return manga(await get('/api/titles/' + encodeURIComponent(mangaId)));
    },
    async getChapters({mangaId}) {
      const response = await get('/api/titles/' +
        encodeURIComponent(mangaId) + '/chapters');
      return array(response.items).map(input => {
        const row = record(input);
        if (!Number.isFinite(row.number)) throw invalid();
        return {
          id: text(row.id), title: text(row.title), number: row.number,
          uploadedAt: row.uploadedAt ?? null,
          access: {type: 'available', availableAt: null,
            priceLabel: null, message: null},
        };
      });
    },
    async getPages({chapterId}) {
      const response = await get('/api/chapters/' +
        encodeURIComponent(chapterId) + '/pages');
      return array(response.images).map((imageUrl, index) => ({
        index, imageUrl: text(imageUrl),
      }));
    },
    async getRecommendations({mangaId, page = 1}) {
      const response = await get('/api/titles/' +
        encodeURIComponent(mangaId) + '/recommendations', {page});
      if (typeof response.hasNextPage !== 'boolean') throw invalid();
      return {items: array(response.items).map(manga),
        page, hasNextPage: response.hasNextPage};
    },
  };
}

В примере сайт возвращает {items: [...]} для каталогов и глав, объект тайтла для карточки, {images: [...]} для страниц и {items: [...], hasNextPage: boolean} для рекомендаций. Парсер должен учитывать реальные ответы вашего сайта.

Возвращайте JSON-данные: null для отсутствующих полей, массивы для списков. Не передавайте undefined, NaN, функции и DOM-объекты. URL изображений должны быть абсолютными. Нумерация страниц каталога начинается с 1, PageDto.index — с 0, без пропусков и дубликатов. ID глав должны быть уникальными, номера — конечными; дробные номера сохраняйте. Даты передавайте в ISO-8601 с часовым поясом, желательно UTC, либо как null.

В ChapterDto.access различайте available, temporarilyUnavailable и paid. Если сайт отдаёт availableAt, priceLabel и message, сохраняйте их. Платный доступ передавайте как ограничение чтения, а не сетевую ошибку. Источник только с метаданными тоже реализует обязательные методы глав и страниц, но возвращает пустые массивы.

4. HTTP, HTML и изображения

Отправляйте запросы через ctx.http.request. Приложение подставляет сессию источника и применяет сетевые разрешения. На каждом перенаправлении оно заново проверяет HTTPS, origin, порт и разрешения.

Авторизацию объявляйте в manifest; не задавайте Cookie, Authorization, Host или User-Agent вручную. Для userAgentProfile выберите app, browser, reader или mobileSafari. Referer и Origin должны относиться к разрешённым origins. Поддерживаемые публичные API-заголовки перечислены в справочнике HTTP ниже.

Извлекайте связанные поля HTML одной вложенной проекцией:

const response = await ctx.http.request({
  method: 'GET', url: new URL('/catalog', ctx.baseUrl).href,
  responseType: 'text',
});
const cards = await ctx.html.extract(response.body, {
  baseUrl: response.url, selector: '.title-card', all: true,
  fields: {
    title: {selector: 'h3', text: true},
    href: {selector: 'a', attr: 'href', absoluteUrl: true},
    cover: {selector: 'img', attr: 'data-src', absoluteUrl: true},
  },
});

Выполняйте пример внутри асинхронного метода источника и добавьте разрешение html. Проекция возвращает данные, а не DOM-узлы. Доступны fields, all, required, text, attr, absoluteUrl, html, outerHtml, ascend, nextSibling, directChildren и tagName.

exclude исключает подходящие дочерние узлы из текстовой проекции. normalizeWhitespace: false сохраняет внутренние пробелы. containsText: ["term"] проверяет наличие 1–8 буквальных подстрок длиной до 256 символов и возвращает boolean. Регулярные выражения не выполняются; совмещать этот режим с другим режимом результата в одном узле нельзя.

getPages возвращает URL изображений. Медиа-брокер приложения загружает и кеширует обложки и страницы с нужными заголовками и сессией. Сохраняйте подписанные параметры URL CDN. Поддерживаемые преобразования изображений задаются через media.transform; произвольный декодер из manifest не выполняется.

5. Фильтры, настройки и авторизация

Фильтры: полный контракт

Декларация, запрос и ответ — разные данные

  1. Источник объявляет capability filters и реализует getFilters({refresh?}).
  2. getFilters возвращает массив FilterDto, а не {filters: [...]}, выбранные значения или параметры HTTP. Порядок массива — порядок фильтров; порядок options — порядок вариантов.
  3. Приложение строит интерфейс по этому массиву и передаёт выбор в search({searchTerm, page, selectedFilters}).
  4. Источник самостоятельно переводит этот выбор в API/HTML-запрос сайта и возвращает MangaDto[]. Автоматического сопоставления ключей с query/body сайта нет.
interface FilterOptionDto {
  value: string;
  label: string;
  caption: string | null;
}
interface FilterDto {
  key: string;
  label: string;
  caption: string | null;
  kind: 'toggle' | 'text' | 'singleSelect' | 'multiSelect'
      | 'triStateMultiSelect' | 'sort';
  options: FilterOptionDto[];
  defaultValues: string[];
  supportsDirection?: boolean;
}
interface SourceQueryDto {
  searchTerm: string;
  page: number;
  selectedFilters: Record<string, string[]>;
}
Поле FilterDto Контракт
key Непустая стабильная строка, уникальная во всём списке фильтров. По ней приходит выбор. genres, format, sort — соглашения об именовании, не обязательные имена.
label Непустая подпись для пользователя. Не используйте её как API ID.
caption Пояснение или null; это обычный текст, без HTML-виджетов.
kind Ровно один из шести типов в таблице ниже; произвольные типы не поддерживаются.
options Массив {value, label, caption}. Для toggle/text передавайте []; для остальных перечисляйте доступные варианты.
defaultValues Массив API values. Непустой массив разрешён только для multiSelect, все значения должны присутствовать в options. Для других типов — [].
supportsDirection Необязательный boolean, по умолчанию true. Имеет смысл у sort; false скрывает выбор направления.

В FilterOptionDto поле value содержит строковый ID, label — непустое название для пользователя, caption — пояснение или null. Числовые ID сайта тоже передавайте строками, например "42"; преобразуйте их только при запросе к API, которому нужно число. Значения внутри фильтра должны быть уникальными. Разным значениям лучше давать разные подписи, иначе чипы будет трудно различить.

У нейтрального варианта вроде «Любой» допускается value: "". В singleSelect и sort он очищает выбор. Пустая строка не может быть значимым ID или входить в defaultValues. Для toggle и text интерфейс не использует options.

Возвращайте объявленные поля явно: caption: null, options: [] и defaultValues: [], когда значений нет. Некоторые пропущенные массивы принимаются для совместимости, но в новом источнике лучше возвращать полный DTO.

Ограничения декодирования: до 256 фильтров, до 10000 options и 10000 defaultValues на фильтр. Строки key/label/value/caption — до 16384 символов без NUL; обязательные строки не должны состоять из пробелов. Выбирайте короткие машинные ключи, особенно для filterBindings, где длина ссылки на ключ ограничена 128 символами. Дубли ключей, дубли values, неизвестный kind, неверный supportsDirection и неподдерживаемые defaults отклоняют весь список.

Как передаётся выбор каждого типа

Значение каждого ключа в selectedFilters — string[]. Boolean, числа, null, вложенные объекты и одиночные строки здесь недопустимы. Ключи и значения вариантов чувствительны к регистру; не переводите и не кодируйте их для URL до передачи источнику.

kind Пример записи в selectedFilters Нейтральное состояние и обработка
toggle "availableOnly": ["true"] Выключенный переключатель удаляет ключ. Проверяйте values.includes("true"); строки "false" UI не отправляет.
text "author": ["Name One, Name Two"] Одна строка в первом элементе. Пустой текст удаляет ключ. Не ожидайте массив отдельных терминов.
singleSelect "format": ["manga"] Один API value. Нет выбора — ключ отсутствует; [] тоже трактуйте как отсутствие выбора.
multiSelect "languages": ["en", "ru"] Значения без префиксов. Отсутствующий ключ означает defaults, явный [] — снять всё.
triStateMultiSelect "genres": ["include:action", "exclude:horror"] Для каждого value — ignore/include/exclude. Ignore не передаётся; пустой выбор удаляет ключ.
sort "sort": ["latest", "desc"] или ["title", "asc"] Первый элемент — поле, второй — направление. Без второго UI подразумевает desc. При supportsDirection=false передаётся только ["latest"].

Текстовый редактор может показывать термины чипами и соединять активные термины через ,, но источник всё равно получает одну строку. Общего формата CSV, списка ID авторов или поискового синтаксиса нет. Разберите строку в источнике, а правила объясните в caption. Сохраняйте алиасы вроде name | alias целиком.

Для triState объявляйте значение без префикса, например value: "action". Выбор придёт как "include:action" или "exclude:action". Поддерживаются только эти префиксы; -action, !action, boolean и ignore:action недопустимы. Удаляйте только первый префикс и сохраняйте оставшуюся часть ID вместе с возможными двоеточиями.

В интерфейсе нельзя одновременно включить и исключить один вариант. В старых сохранённых фильтрах конфликты или удалённые варианты всё же возможны: убирайте дубли, сверяйте значения с актуальными вариантами и определите правило разрешения конфликтов. Defaults, очистка и сброс

Пусть объявлено languages.defaultValues = ["en", "ru"]:

Состояние Значение для сайта
selectedFilters = {} en и ru — defaults
{"languages": ["ja"]} Только ja
{"languages": []} Явно ни одного языка; defaults не восстанавливаются
{"languages": ["en", "ru"]} То же, что defaults; UI может удалить этот ключ как избыточный
Общая кнопка сброса фильтров Выбор становится {}, поэтому defaults снова действуют

MangaLaunch использует значения по умолчанию для отображения multiSelect, но не добавляет их в selectedFilters. Применяйте их в источнике, когда ключ отсутствует. Используйте selectedFilters.languages ?? defaults: проверка длины ошибочно заменит явный [], которым пользователь очистил фильтр.

У остальных типов нет начального выбора через декларацию. defaultValue, selected, checked и min/max не входят в FilterDto. Начальный порядок задавайте в getPopular, getLatest и search, а не в defaultValues фильтра сортировки.

Явные пустые массивы передаются источнику без изменений. Записи с непустым массивом из одних пробельных строк удаляются перед запросом; не используйте их как управляющий сигнал.

Маршрутизация каталога и сортировка

  • Пустой searchTerm и пустой selectedFilters: обзор вызывает getPopular, последние — getLatest.
  • Текст поиска или любая запись selectedFilters, включая явный []: вызывается search. Поэтому search должен поддерживать searchTerm: "", а не только поиск по названию.
  • В отфильтрованной ленте без поискового текста приложение может добавить сортировку первой декларации kind=sort: latest/new для последних либо popular/discover для обзора, по совпадению в value или label. Пользовательский выбор не заменяется.
  • Если подходящего варианта нет, источник сам выбирает порядок по умолчанию. В SourceQueryDto нет feedKind или отдельного признака «вызвано из последних»; не выводите его из порядка вызовов.
  • getLatest должен использовать ту же серверную сортировку, что явный соответствующий выбор фильтра. supportsDirection: false означает фиксированный порядок API; игнорируйте оставшееся направление в старом preset.
  • После смены поиска/фильтров пагинация начинается с 1. Не храните один общий cursor для разных выборок или одновременных операций; если API использует cursors, изолируйте их по нормализованному запросу.

Полный модуль обработки всех шести типов

Сохраните следующий пример как src/catalog-filters.mjs. Замените language[], genre[] и остальные вымышленные параметры на реальные. Повторяющиеся параметры добавляйте через append: String(array) сформирует другой запрос.

const choices = {
  format: [['manga', 'Manga'], ['manhwa', 'Manhwa']],
  languages: [['en', 'English'], ['ru', 'Russian'], ['ja', 'Japanese']],
  genres: [['action', 'Action'], ['drama', 'Drama'], ['horror', 'Horror']],

    ['latest', 'Latest updates'], ['title', 'Title']],

const allowed = Object.fromEntries(Object.entries(choices)
  .map(([key, rows]) => [key, new Set(rows.map(([value]) => value))]));
const languageDefaults = ['en', 'ru'];
const options = key => choices[key].map(([value, label]) => ({
  value, label, caption: null,
}));

export function catalogFilters() {
  return [
    {key: 'availableOnly', label: 'Available only', caption: null,
      kind: 'toggle', options: [], defaultValues: []},

      kind: 'text', options: [], defaultValues: []},

      kind: 'singleSelect', options: options('format'), defaultValues: []},

      kind: 'multiSelect', options: options('languages'),
      defaultValues: [...languageDefaults]},
    {key: 'genres', label: 'Genres', caption: null,
      kind: 'triStateMultiSelect', options: options('genres'), defaultValues: []},
    {key: 'sort', label: 'Order', caption: null,
      kind: 'sort', options: options('sort'), defaultValues: [],

export function buildSearchRequest(ctx, query = {}) {
  const selected = query.selectedFilters ?? {};
  const values = key => Array.isArray(selected[key])
    ? selected[key].filter(value => typeof value === 'string') : [];
  const known = key => [...new Set(values(key))]
    .filter(value => allowed[key].has(value));
  const searchTerm = typeof query.searchTerm === 'string' ? query.searchTerm : '';
  const page = Number.isSafeInteger(query.page) && query.page >= 1 ? query.page : 1;
  const url = new URL('/api/titles', ctx.baseUrl);
  url.searchParams.set('page', String(page));
  if (searchTerm.trim()) url.searchParams.set('q', searchTerm);

  if (values('availableOnly').includes('true')) {
    url.searchParams.set('available', 'true');
  }
  const author = values('author')[0];
  if (author?.trim()) url.searchParams.set('author', author);
  const format = known('format')[0];
  if (format) url.searchParams.set('format', format);

  // An absent key applies defaults; an explicit [] removes every language.
  const languages = Array.isArray(selected.languages)
    ? known('languages') : languageDefaults;
  for (const value of languages) url.searchParams.append('language[]', value);

  const included = new Set();
  const excluded = new Set();
  for (const raw of values('genres')) {
    if (raw.startsWith('include:') && allowed.genres.has(raw.slice(8))) {
      included.add(raw.slice(8));
    } else if (raw.startsWith('exclude:') && allowed.genres.has(raw.slice(8))) {
      excluded.add(raw.slice(8));
    }
  }
  // Normal UI input is exclusive. For a conflicting stale selection,
  // this example gives inclusion priority.
  for (const value of included) {
    excluded.delete(value);
    url.searchParams.append('genre[]', value);
  }
  for (const value of excluded) url.searchParams.append('excludeGenre[]', value);

  const rawSort = values('sort');
  const sort = allowed.sort.has(rawSort[0])
    ? rawSort[0] : searchTerm.trim() ? 'relevance' : 'popular';
  url.searchParams.set('sort', sort);
  url.searchParams.set('direction', rawSort[1] === 'asc' ? 'asc' : 'desc');
  return {method: 'GET', url: url.href, responseType: 'json'};
}

export function createCatalogMethods(ctx, mapManga) {
  async function search(query) {
    const response = await ctx.http.request(buildSearchRequest(ctx, query));
    if (!response.body || !Array.isArray(response.body.items)) {
      throw Object.assign(Error('Invalid catalog response.'),
        {code: 'parse_error', phase: 'parse'});
    }
    return response.body.items.map(mapManga);
  }
  return {
    async getFilters() { return catalogFilters(); },
    search,
    getPopular({page = 1} = {}) {
      return search({page, searchTerm: '',
        selectedFilters: {sort: ['popular', 'desc']}});
    },
    getLatest({page = 1} = {}) {
      return search({page, searchTerm: '',
        selectedFilters: {sort: ['latest', 'desc']}});
    },
  };
}

Для подключения к примеру из раздела 3 импортируйте createCatalogMethods из ./catalog-filters.mjs и вызовите const catalog = createCatalogMethods(ctx, manga) внутри createSource. Включите ...catalog в возвращаемый объект вместо прежних getPopular, getLatest, search и getFilters. Методы карточки, глав, страниц и рекомендаций оставьте из раздела 3.

Модуль обрабатывает:

  • Возвращает декларации для каждого поддержанного kind и применяет defaults также в обычном каталоге.
  • Читает только известные ключи и API values; неизвестные старые значения игнорирует. Не передаёт URL, произвольные поля сортировки или фрагменты запросов из selectedFilters.
  • Сохраняет значения текста, корректно кодирует специальные символы один раз, разбирает include/exclude, повторяемые параметры и asc/desc.
  • Не хранит состояние активного запроса; несколько search могут работать одновременно.

Преобразуйте selectedFilters в формат запроса сайта: параметры GET, JSON POST или form POST. Источник сам подставляет ID, числа, массивы включения и исключения, поля тела запроса. Для формы передайте строку URLSearchParams и нужный Content-Type: объект тела запроса автоматически в форму не преобразуется.

Отдельных типов для диапазонов, групп, зависимых списков, удалённого автодополнения, собственного HTML или элементов управления нет. Диапазон можно задать двумя фильтрами text и проверить границы при построении запроса. Выпадающему списку нужен готовый плоский массив options: getFilters не получает строку для поиска вариантов.

Динамические options и refresh

Если варианты на сайте могут меняться, объявите supportsFilterRefresh: true. Обновление пользователем вызывает getFilters({refresh: true}); обычные вызовы передают false или не передают аргумент. MangaLaunch кеширует успешные снимки и объединяет обычные параллельные чтения. Неудачную загрузку можно повторить. Поиск и список последних могут запрашиваться до getFilters.

Кеш источника храните внутри фабрики. Вспомогательный модуль src/filter-cache.mjs поддерживает принудительное обновление:

export function cachedFilterLoader(loadFilters) {
  let snapshot;
  let pending;
  let generation = 0;
  return async function getFilters({refresh = false} = {}) {
    if (refresh) {
      generation++;
      snapshot = undefined;
      pending = undefined;
    }
    if (snapshot !== undefined) return snapshot;
    if (pending) return pending;
    const current = generation;
    const task = Promise.resolve().then(loadFilters).then(filters => {
      if (!Array.isArray(filters)) {
        throw Object.assign(Error('Invalid filter response.'),
          {code: 'parse_error', phase: 'parse'});
      }
      if (generation === current) snapshot = filters;
      return filters;
    });
    pending = task;
    try { return await task; }
    finally { if (pending === task) pending = undefined; }
  };
}

Внутри createSource используйте const getFilters = cachedFilterLoader(() => loadFiltersFromSite(ctx)). Функция загрузки должна проверять ответ и возвращать полный FilterDto[] со стабильными значениями. Вспомогательный модуль не кеширует ошибки и не даёт старому ответу перезаписать новый снимок. Для статических фильтров кеш и обновление не нужны.

В сохранённых фильтрах и позициях используются key и value. Подпись можно изменить без потерь, а переименование ключа или значения нарушит связь. Определите и опишите, как обрабатывать варианты, удалённые сайтом. Если загрузить варианты не удалось, верните ошибку, а не пустой список.

Чипы тайтла и filterBindings

filterBindings связывает чипы карточки тайтла с фильтрами. Допустимы роли author, artist и tags; значение каждой роли — ключ фильтра, а не ID варианта. Например: {"author": "author", "tags": "genres"}.

  • Author/artist связываются с kind=text и передают полное отображаемое имя одной строкой. При необходимости источник разрешает имя в API ID внутри search.
  • Общий MangaDto.tags может содержать жанры, теги, темы и формат. Для них приложение сопоставляет подписи чипов с option.label подходящих singleSelect/multiSelect/triStateMultiSelect.
  • Точное совпадение подписи важнее частичного; binding помогает при равенстве совпадений. Совпадение жанра может выбрать фильтр genres даже при предпочтительном binding на tags.
  • Для triState нажатый чип становится include:value; для single/multi — обычным value. При отсутствии option возможен подходящий text-фильтр; если сопоставления нет, открывается текстовый поиск.
  • Возвращайте чистые совпадающие названия, без badge-счётчиков, служебных дочерних надписей и HTML. Не теряйте полные алиасы авторов.

Обязательные тесты фильтров

Проверьте каждый тип с отсутствующим ключом, явным [], значением по умолчанию и очищенным выбором. Проверьте сброс, все поля и направления сортировки, сортировку без выбора направления, include/exclude/ignore, конфликты и удалённые варианты. Добавьте текст с запятыми и спецсимволами, фильтрацию при пустом searchTerm, смену фильтров после первой страницы, одновременные разные выборки, обновление после ошибки и гонку старого и нового ответов. 6. Производительность, ограничения и ошибки

  • Каждый sourceId имеет отдельные настройки, cookies, токены и браузерный профиль, даже при общем сайте или engine.
  • Несколько методов одной фабрики могут выполняться одновременно: по умолчанию 3 операции, пользователь выбирает 1–5. Не храните текущий mangaId, page, временный ответ или изменяемый cursor в общем поле фабрики. Используйте локальные переменные аргументов.
  • Для независимых запросов подходит Promise.all в пределах лимитов. Не распараллеливайте зависимые шаги авторизации и пагинацию с общим серверным cursor.
  • Для парных Details/Chapters/Recommendations одной страницы переиспользуйте одну загрузку и проекцию через recent: импортируйте helper в свой проект и создавайте кеш внутри фабрики. По умолчанию это 2 записи и 15 секунд после завершения; одинаковые выполняющиеся запросы объединяются, ошибки удаляются. Каталог с ручным обновлением, POST и операции записи этим кешем не обслуживаются.
  • В пакет включаются только используемые исходники, данные, иконки и лицензия. Тесты, node_modules, служебный код SDK и закрытые ключи в архив не входят.

node tools/pack_extension.mjs --project ./my-sources --key .keys/publisher.pem --key-id my-publisher-2026 --output ./dist/my-sources.mlsource

Упаковщик создаёт .mlsource, .mlsource.public.json и .mlsource.sha256: записывает хеши и размеры файлов, подписывает manifest и проверяет архив. При одинаковых файлах, версии и ключе получается одинаковый пакет.

Импортируйте запись публичного ключа и пакет в настройках расширений. По независимому каналу сверьте SHA-256 отпечаток ключа и разрешённые extensionIds, затем подтвердите издателя и разрешения. Файл .public.json рядом с архивом помогает сверить значения, но сам по себе не подтверждает доверие к издателю. Для локальных тестов используйте отдельный ключ.

9. Публикация на GitHub

Ручной выпуск собственного пакета

И для ручного выпуска, и для CI действуют следующие правила:

  1. Выпускайте проверенный commit с новой SemVer-версией; опубликованную версию и её байты не перезаписывайте.
  2. extensionId, source IDs и publisher key сохраняйте при обычном обновлении. Смену или отзыв ключа оформляйте явно; новый ключ из скачанного пакета не может сам себя одобрить.
  3. Добавьте подписанный индекс, связывающий репозиторий, версию, tag, архив, hash и source IDs:
node tools/sign_repository_index.mjs --repo owner/repo --serial 1 --tag v1.0.0 --package ./dist/my-sources.mlsource --key .keys/publisher.pem --output ./dist

serial — положительный, строго возрастающий номер индекса репозитория. Сохраняйте последовательность при переносе workflow и не подписывайте разные данные с одним номером. Срок действия индекса — 30 дней; обновляйте его до истечения срока. extensions-index.ed25519 — отдельная бинарная подпись, не JSON и не base64. Подписывать нужно и индекс, и пакет.

Для ручного выпуска создайте тег на проверенном коммите и приложите к GitHub Release пять файлов:

git tag v1.0.0
git push origin v1.0.0
gh release create v1.0.0 ./dist/my-sources.mlsource ./dist/my-sources.mlsource.public.json ./dist/my-sources.mlsource.sha256 ./dist/extensions-index.json ./dist/extensions-index.ed25519 --repo owner/repo --verify-tag --title "My Unofficial Sources 1.0.0" --notes "Signed source package."

Для предварительного выпуска добавьте суффикс SemVer и отметьте релиз на GitHub как prerelease. В описании укажите изменения источников, минимальную версию приложения, новые разрешения и то, что не удалось проверить. Публикуйте пакет, запись публичного ключа, контрольную сумму и подписанный индекс. Закрытый ключ не публикуйте.

Автоматизация публикации

Процесс выпуска можно посмотреть в репозитории официального расширения. В своём проекте защитите основную ветку и создайте защищённое окружение выпуска со своими ключами и настройками:

  • Variable MLSOURCE_PUBLISHER_KEY_ID — идентификатор доверенного ключа издателя.
  • Secret MLSOURCE_SIGNING_KEY_BASE64 — base64 полного приватного Ed25519 PEM в формате PKCS#8. Подготовьте значение локально и храните только как секрет environment.
  • При необходимости добавьте reviewers и ограничения release tags.

В этом workflow выпуск запускается SemVer-тегом vVERSION. При ручном запуске выберите существующий тег или ref и передайте версию без v; тег должен указывать на выполняемый коммит. Workflow повторяет тесты, подписывает пакет и индекс, затем публикует пять файлов. Номер индекса вычисляется как GITHUB_RUN_NUMBER * 100 + GITHUB_RUN_ATTEMPT. При адаптации сохраните строгое возрастание номера между всеми выпусками.

Проверки pull request и основной ветки создают тестовые файлы, а не релизы. Доступ к закрытому ключу дайте только защищённому окружению выпуска. Перед установкой обновления MangaLaunch проверяет подписи, версии, владение ID источников и необходимые подтверждения пользователя.

10. Справочник контрактов API v1

Справочник описывает данные, которыми источник обменивается с MangaLaunch. Ответы сайта могут выглядеть иначе: источник преобразует их к этим контрактам. Полные определения полей находятся в source-api.d.ts и схемах SDK. Неизвестные поля manifest отклоняются. Добавление поля в DTO не создаёт новую возможность интерфейса.

Поле HTTP-запроса Правила
method, url, responseType Обязательны; метод разрешён network.methods. URL — HTTPS без credentials и fragment, в разрешённом origin с тем же портом. В сетевом брокере URL ограничен 8192 символами.
headers Необязательный объект до 16 строковых заголовков. Имена без учёта регистра, дубли после нормализации запрещены; значение до 4096 символов без управляющих символов.
body Только для POST. Строка отправляется как UTF-8 текст; другие JSON-значения — как JSON. Объект не превращается в form автоматически. Отсутствующий/null body не отправляется.
timeoutMs По умолчанию 20000, целое 250–30000. Включает ожидание очереди, перенаправления и обработку ответа.
userAgentProfile Приоритет: поле запроса → network.userAgentProfile → app. Media имеет отдельный media.userAgentProfile. При необходимости согласуйте HTTP, WebView и media с реальным сценарием сайта.
authRevision Неотрицательное безопасное целое из getSession; требует sourceSession. Это защита от использования устаревшего снимка, а не токен.

Разрешённые request headers: Accept, Content-Type, Accept-Language, Site-Id, X-Service-Name, X-Requested-With, X-Client-Version, HX-Request, App-Id, App-Version; дополнительно разрешены проверяемые Referer и Origin. Другие произвольные заголовки не принимаются. Origin должен быть ровно origin без пути; Referer может содержать путь разрешённого сайта.

При строковом body Content-Type по умолчанию text/plain; charset=utf-8, при JSON body — application/json, если заголовок не задан явно. Пример form POST внутри асинхронного метода:

const body = new URLSearchParams({q: 'A & B', page: '1'}).toString();
const response = await ctx.http.request({
  method: 'POST',
  url: new URL('/api/search', ctx.baseUrl).href,
  responseType: 'json',
  headers: {'Content-Type': 'application/x-www-form-urlencoded; charset=utf-8'},
  body,
});

HEAD может проверять также разрешённый image origin и не возвращает тело изображения. GET не принимает body. После GET/HEAD обрабатываются до 5 redirects с повторной проверкой URL и сессии; redirect POST не воспроизводится автоматически.

Успешный ответ содержит конечный url, status, body и безопасные headers с ключами в нижнем регистре: content-type, content-length, cache-control, etag, last-modified, retry-after, location, x-total-count, cf-mitigated. Set-Cookie не передаётся скрипту; приложение применяет cookies отдельно в разрешённой сессии.

responseType: "text" возвращает строку, "json" — разобранное JSON-значение, "bytes" — массив чисел от 0 до 255. Приложение учитывает объявленную HTTP-кодировку, в том числе Windows-1251. Не скрывайте ошибки неподдерживаемой кодировки или повреждённого JSON.

Не-2xx ответ вызывает SourceHostError: 401 → auth_required, 403 → access_denied, 404 → not_found, 429 → rate_limited, прочие → invalid_response; при cf-mitigated: challenge — challenge_required. При необходимости разбирайте безопасный error.body своего endpoint для определения доступа. Не рассчитывайте получить обычный response.status=404 вместо исключения.

10.3. Все поля HTML-проекции

У каждого узла проекции ровно один режим результата: fields, text=true, attr, html=true, outerHtml=true, tagName=true или containsText. Остальные поля управляют выбором узлов. baseUrl задаётся на верхнем уровне вызова ctx.html.extract и наследуется вложенными полями.

Поле Тип и действие
baseUrl Необязательный абсолютный HTTPS URL для разрешения ссылок; используйте конечный response.url.
selector CSS selector, 1–1024 символа; без selector используется текущий узел. Скрипты/браузерные обработчики не выполняются.
fields Объект до 64 именованных вложенных проекций; имя результата 1–256 символов.
all Boolean; true возвращает массив, иначе первый результат либо null.
required Boolean; отсутствие узла, null или пустая строка приводят к ошибке.
text Boolean; true возвращает trim/нормализованный текст узла.
attr Имя HTML-атрибута, 1–128 символов из букв/цифр/_/:-; отсутствующий атрибут даёт null.
html / outerHtml Boolean; соответственно содержимое элемента или элемент целиком. Используйте только когда проекции полей недостаточно.
absoluteUrl Boolean; разрешает непустую строку ссылки относительно baseUrl, результат должен быть HTTPS.
textEquals Строка до 4096 символов; точное сравнение с нормализованным текстом, с учётом регистра.
ascend Целое 0–8; подняться к родителю после выбора узла.
nextSibling Boolean; после ascend перейти к следующему element sibling, не текстовому узлу.
directChildren Boolean; оставить только непосредственных детей текущего узла.
tagName Boolean; true возвращает имя тега в нижнем регистре.
exclude CSS selector до 1024 символов; только совместно с text=true, исключает потомков из копии узла.
normalizeWhitespace Boolean; только для text=true. false сохраняет внутренние пробелы, но внешние всё равно обрезаются.

Глубина вложенности — до 8, совпадений CSS selector — до 10000. Бюджет всего результата — до 100000 узлов и 1 Ми символов текстов/ключей. tokenCookieNames Точные имена cookies с токеном; требуют bearer=true, wildcard запрещён. Значение декодируется из cookie.

Списки rules — до 16 строк, каждая 1–128 символов; tokenType — до 32. sessionExport.headers допускает Cookie, Authorization, X-XSRF-TOKEN, X-CSRF-TOKEN, а values — accessToken и csrfToken. Экспортируйте только необходимое.

ctx.auth.status() возвращает authorized и revision текущего источника. getSession({url}) возвращает снимок для указанного разрешённого URL. headers, cookieHeader, accessToken и csrfToken доступны только при разрешённом в manifest экспорте. Перед использованием проверяйте необязательные значения: не превращайте undefined в строку. При выходе или смене аккаунта снимок меняется. Обычные HTTP-запросы получают актуальную сессию автоматически.

Ограничения min/max допустимы только у integer, maxLength — только у string, options — только у enum. Без явных границ integer использует -1000000…1000000, string — maxLength=4096. Строковые настройки не принимают управляющие символы; default проверяется теми же правилами, что пользовательское значение.

10.6. Ошибки и диагностический контракт

SourceHostError — это Error с полями code и phase. Дополнительно могут быть httpStatus, retryAfterSeconds, access и body. В phase указывайте короткое название этапа, а не стек, HTML или токен. Сохраняйте коды ошибок приложения; к собственным ошибкам добавляйте code и phase.

Полный union кодов API v1:

cancelled, timeout, offline, network, rate_limited, auth_required,
challenge_required, not_found, title_not_found, chapter_not_found,
chapter_unavailable, parse_error, invalid_response, permission_denied,
unsupported, incompatible_api, resource_limit, runtime_crashed,
auth_session_changed, source_unavailable, access_denied

not_found означает, что ресурс не найден; title_not_found и chapter_not_found уточняют, какой именно. chapter_unavailable с полем access описывает ограничение чтения. permission_denied означает нарушение разрешений или контракта вызова, unsupported — недоступную возможность, resource_limit — исчерпанный бюджет. Отмену и смену сессии передавайте как ошибки, а не пустые результаты.

ctx.log.info принимает название события и объект со строками, числами или boolean. Не записывайте в лог ответы сервера, объекты Error, cookies и персональные данные.

10.7. Контракт подписанного индекса

Индекс — объект schemaVersion=1, repositoryId (owner/repo в нижнем регистре), serial, generatedAt, expiresAt, publisherKeyId, channel и packages. channel: stable/prerelease; timestamps — UTC с секундной точностью и Z.

Каждая запись packages содержит extensionId, version, releaseTag, assetName, size, sha256, sourceApiVersion, minRuntimeAbi, minAppVersion, sourceIds и channel. Эти значения сверяются с независимо проверенным архивом. Не указывайте внешний download URL вместо assetName. Схема допускает до 128 пакетов, но предоставленный sign_repository_index.mjs формирует индекс одного переданного архива.

Канонический manifest подписывается Ed25519 с префиксом MangaLaunch source package v1\n, индекс — с MangaLaunch source repository v1\n. Подписи не взаимозаменяемы. Для получения канонических байтов используйте упаковщик и утилиту подписи индекса. После истечения срока индекса обновление метаданных прекращается, но установленный пакет может работать без сети. Старый архив или удаление репозитория не отменяют отзыв и закрепление ключа.
