# Ссылки перед публикацией

Все публичные адреса задаются в одном файле — [site-config.js](site-config.js). Сейчас значения `null`: сайт показывает заглушки и никуда не отправляет посетителя. После заполнения кнопки автоматически становятся ссылками в обеих языковых версиях.

| Поле | Что указать | Где появится |
| --- | --- | --- |
| `windowsDownload` | Полный HTTPS-адрес релиза или файла для Windows | Кнопка Windows в блоке скачивания |
| `androidDownload` | Полный HTTPS-адрес релиза или APK для Android | Кнопка Android в блоке скачивания |
| `telegram` | Полный HTTPS-адрес вашего публичного канала или чата | Telegram в подвале обеих страниц |

Пример структуры — замените адреса своими, не публикуйте их буквально:

```js
window.SITE_LINKS = Object.freeze({
  windowsDownload: 'https://example.org/windows-release',
  androidDownload: 'https://example.org/android-release',
  telegram: 'https://t.me/YOUR_PUBLIC_CHANNEL',
});
```

Можно заполнить только готовые адреса, остальные оставить `null`. Поддерживаются только HTTPS-ссылки без логина и пароля в адресе. При заполнении Telegram надпись «Скоро» исчезает. Когда заданы обе загрузки, скрывается сообщение об отсутствии ссылок на скачивание.

## Что менять не нужно

- Ссылки на руководство, разделы страницы, контракты, шаблон и инструменты относительные: они работают и на основном домене, и в подпапке GitHub Pages.
- Внутренние кнопки «Get the app / Скачать» ведут к блоку загрузки. Назначать им внешний адрес отдельно не требуется.
- Адреса `example.org`, `owner/repo`, `my-publisher-2026`, `en.example` и `example.sources` **в руководстве** — примеры для авторов расширений. Это не настройки сайта. Каждый автор заменяет их в собственном проекте.
- Внешние ссылки на общую документацию GitHub менять не нужно.

## Настройки GitHub Pages

1. Разместите содержимое этой папки в корне своего репозитория, включая `.github`.
2. Выберите **Settings → Pages → Source → GitHub Actions**.
3. Workflow по умолчанию отслеживает ветку `main`. Если у вас другая ветка, замените её в `.github/workflows/pages.yml`.
4. При желании подключите собственный домен через настройки Pages. Сейчас домен и файл CNAME не заданы.

Публикуйте только файлы из списка в workflow. Этот документ, тесты и внутреннее ТЗ в публичный артефакт не входят. Токены, пароли, приватные ключи издателя и OAuth-секреты в настройки статического сайта не добавляйте.
